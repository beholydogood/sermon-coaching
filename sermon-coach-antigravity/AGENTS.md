# 설교 스피치 코칭 앱 개발 지침

이 저장소는 Google Antigravity에 전달할 제품 자료로 시작한다. 당신의 역할은 이 자료를 읽고 앱을 구현·개선하는 개발 에이전트다. 코칭 모델의 페르소나를 개발 에이전트 자신의 역할로 오인하지 않는다.

## 자료를 읽는 순서

1. `README_KO.md`
2. `docs/PRODUCT_BRIEF.md`
3. `prompts/sermon_speech_coach_prompt.md`
4. `docs/sermon_app_spec.md`
5. `references/sermon_reference_library.md`
6. `references/kim_woojun_speech_strengths.md`
7. `qa/ACCEPTANCE.md`

## 구현에서 지킬 핵심 조건

- 사용자에게는 한국어로 간결하게 안내한다. 기존 프로젝트가 있으면 현재 구조·설정·변경 사항을 먼저 확인하고 그 환경에 맞게 구현한다.
- 코칭 모델의 기본 지침은 `prompts/sermon_speech_coach_prompt.md`의 구분선 아래 전체 내용이다. 모델 요청에는 실제 접근 자료·대상 선별·맥락·이전 기록·참고 클립을 별도 입력으로 제공한다. 문서 앞부분의 사용 안내는 모델 지침과 분리한다.
- 개발 에이전트에게 이 문서를 읽혔다는 사실을 앱 내부의 코칭 모델에 프롬프트를 연결한 것으로 간주하지 않는다. 실제 요청 경로에서 사용되도록 구현한다.
- 대상 설교자와 설교 구간 확인을 분석의 선행 조건으로 둔다. 다른 사람과 다른 예배 순서의 말·표정·동작을 대상자의 코칭·측정·이력에 넣지 않는다.
- 대상 음성 구간과 대상이 실제 보이는 구간을 각각 관리한다. 화면 전환·수어통역 삽입 화면·인용 영상에서 관찰 주체를 혼동하지 않는다.
- 코칭은 스피치 수행에 집중한다. 신학·영성·인격을 점수화하지 않는다.
- 행사, 전달 방식, 청중, 장면 목적을 독립적으로 저장하고 함께 해석한다. 연령 집단에 대한 고정관념으로 속도·동작·말투를 강요하지 않는다.
- 관찰 사실, 측정, 해석, 연습, 변화 판정을 분리한다. 측정 출처·단위·분모·분석 범위를 보존한다. 원본과 대응하지 않는 장면 시각은 근거로 사용하지 않는다.
- 실제 분석 연결이 없으면 영상을 분석한 것처럼 결과·진행 상태·점수·향상 수치를 생성하지 않는다. 개발용 예시는 명확히 구별하고 실제 사용자 이력과 분리한다.
- 사용자별 기록을 분리하며 저장 성공을 확인한 경우에만 저장됐다고 안내한다. 기존 기록이나 사용자 정정을 덮어쓰지 않는다.
- 참고 자료의 후보·예비 분석·클립 검토·이용 범위 확인 상태를 보존한다. 미검토 후보를 승인된 모범 클립으로 자동 승격하지 않는다.
- 영상의 제목이나 이야기 소재만으로 실제 행사·대상 연령·설교자를 확정하지 않는다. 결혼 이야기를 다룬 주일설교를 결혼식 설교로 분류하지 않는다.
- 배포·영상 수집·새 유료 서비스 가입을 현재 자료만으로 이미 완료된 일처럼 취급하지 않는다. 키·계정 설정이 필요하면 구현 가능한 부분을 먼저 완성하고 필요한 설정 항목만 구체적으로 알린다.

## 확인과 완료 보고

`qa/ACCEPTANCE.md`와 앱 설계 문서의 검증 시나리오를 기준으로 변경에 적절한 확인을 수행한다. 실제 수행한 확인과 수행하지 못한 확인을 구분한다. 마지막에는 실행 방법, 완성된 기능, 실제로 연결된 분석 기능, 남아 있는 설정을 정확하게 보고한다. 계획이나 화면만 만든 상태를 완성된 영상 코칭 앱이라고 보고하지 않는다.
